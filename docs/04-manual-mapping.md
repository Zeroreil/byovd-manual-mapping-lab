# 04 · Manual Mapping（概念与检测）

> 本文件是**概念级分析**，不包含可运行的 manual mapper。公开仓库不提供完整 loader、shellcode、DSE bypass 或入口点调用代码。

## 1. 它是什么

手动映射（manual mapping）是指不通过 Windows 的驱动加载器（`NtLoadDriver` / SCM / PnP），而是由另一个内核组件或已有漏洞原语，把一个 PE 文件按内存镜像布局放进内核地址空间，完成重定位、导入解析，然后直接调用其入口点。

它和“正常加载”的差别：

| 项 | 正常加载 | 手动映射 |
|---|---|---|
| 服务/注册表 | 有 | 通常没有 |
| `PsLoadedModuleList` | 有 | 通常没有 |
| 驱动对象/设备对象 | 由 DriverEntry 创建 | 取决于 payload |
| 文件落盘 | 有 `.sys` | 可能只在内存 |
| 签名检查 | 由 CI 执行 | 绕过/不经过 CI |
| 卸载 | SCM/驱动卸载 | 由 mapper 自行清理 |

## 2. 攻击者为什么用它

- 绕过驱动签名强制（DSE）；
- 不留下服务/注册表/文件痕迹；
- 不进入模块链表，规避 `PsLoadedModuleList` 枚举；
- 可以按需映射、用完即弃。

## 3. 概念阶段

> 下面是**防御分析用的阶段划分**，不是操作指南。

### 阶段 A · 准备镜像

- 获取一个 PE（通常是 `.sys`）；
- 检查节表、镜像基址、大小、重定位、导入表；
- 决定放置位置（池、已有模块空洞、映射区）。

**可观测痕迹**

- 原始 PE 文件（如果落盘）；
- 池中 MZ/PE 头；
- 可执行的非映像内存；
- 与已知样本的节/字符串/导入特征匹配。

### 阶段 B · 分配与复制

- 在内核地址空间分配可执行内存；
- 复制 PE 头与各节；
- 处理节对齐/文件对齐差异。

**可观测痕迹**

- `NonPagedPool` / `NonPagedPoolNx` 中的可执行页；
- 池标签异常；
- 内存保护从 RW → RX 的变化；
- 大量 `MZ`/`PE\0\0` 特征。

### 阶段 C · 重定位

- 如果镜像不是按首选基址加载，修正绝对地址；
- 处理 `.reloc` 节。

**可观测痕迹**

- 内存中 PE 的基址与 `ImageBase` 不一致；
- 重定位节被修改；
- 指向模块/池的绝对指针。

### 阶段 D · 导入解析

- 解析导入表；
- 从 `ntoskrnl` / `hal` / 其他模块获取函数地址；
- 填充 IAT。

**可观测痕迹**

- IAT 指向的地址落在非预期模块；
- 导入函数组合异常（如 `PsLookupProcessByProcessId` + `MmCopyVirtualMemory` + `ZwOpenProcess`）；
- 字符串/符号残留。

### 阶段 E · 入口点

- 调用 `DriverEntry` 或自定义入口；
- payload 创建设备/符号链接/回调/线程。

**可观测痕迹**

- 新设备对象/符号链接没有对应服务；
- 新驱动对象没有对应文件；
- 新回调没有合法模块归属；
- 内核线程/workitem 的起始地址不在已知模块。

### 阶段 F · 清理

- 清除 PE 头；
- 释放临时内存；
- 删除设备/符号链接；
- 恢复被修改的代码/数据。

**可观测痕迹**

- 池中残留的节内容；
- 已释放但仍有引用的对象；
- 句柄/对象生命周期不匹配；
- 代码页与磁盘文件不一致。

## 4. 为什么它容易被发现

手动映射的“隐身”是相对的。防守方可以从多个视角交叉：

1. **模块链表 vs 内存扫描**：链表没有，但池里有 PE/可执行页。
2. **服务 vs 驱动对象**：没有服务，但有 `\Driver\...` 对象。
3. **设备 vs 符号链接**：符号链接删了，但已有句柄仍能 IOCTL。
4. **文件 vs 代码页**：文件删了，但内核代码页仍可执行。
5. **回调 vs 模块归属**：回调地址不在任何已知模块范围内。
6. **池标签/保护**：可执行池、RWX、异常标签。

## 5. 检测清单

| 检查 | 方法 | 误报注意 |
|---|---|---|
| 可执行池 | 枚举池页，查 `MZ`/`PE`、可执行保护 | JIT/驱动可能合法使用可执行池 |
| 模块外代码 | 采样内核栈/回调/线程起始地址，查是否落在已知模块 | 需要符号化基线 |
| 驱动对象无服务 | `\Driver` 对象 vs `Services\` | 某些 legacy 驱动可能无服务 |
| 设备无文件 | 设备对象 vs 驱动文件 | 内存驱动/测试驱动 |
| IAT 异常 | 导入地址 vs 模块范围 | 热补丁/转发导出 |
| 代码完整性 | 磁盘文件哈希 vs 内存页 | 需要安全/可信基线 |

## 6. 缓解

- 开启 HVCI / 内核代码完整性；
- 驱动白名单 + WDAC；
- 监控可执行池与模块外代码；
- 对驱动加载/服务创建/设备打开做关联检测；
- 定期做内核内存基线/差分；
- 禁止普通用户加载驱动。

## 7. 公开边界

本仓库**不提供**：

- 完整 manual mapper；
- DSE/CI bypass；
- 入口点调用、重定位、导入解析的可运行代码；
- 具体 payload 或目标偏移。

这些内容不应进入公开仓库。检测与缓解是本仓库的重点。
